# Saints Studio

Тестовый прототип управления креативным отделом для AFF SAINTS. Автор: Сергей Юрасов, [@myszf](https://t.me/myszf).

**Демо:** https://aff-saints-studio-sergey.navycrab36.chatgpt.site

**AI:** проект сделан с Codex, один ассистент, без субагентов. Подробнее: [AI_WORKFLOW.md](AI_WORKFLOW.md).

## Проверить за пять минут

1. Войти как **байер Алексей**, создать ТЗ со всеми обязательными полями.
2. Справа сверху переключиться на **креативщика Милу**, открыть новую задачу и **Взять в работу**.
3. Записать AI-расход с сервисом и количеством кредитов. **Сдать на проверку** со ссылкой или файлом.
4. Байер нажимает **На правки**, описывает замечания.
5. Исполнитель записывает дополнительные кредиты и сдаёт новую версию.
6. Байер принимает работу. Вкладки **История**, **Результаты**, **AI-расходы** сохраняют обе итерации.
7. Переключиться на **руководителя Анну**, открыть **Аналитика**.

Четыре тестовых пользователя, три роли, шесть начальных задач. Каждый посетитель получает отдельную серверную песочницу. Переключение ролей внутри браузера сохраняет одну команду. Сессия действует 7 дней, данные переживают перезагрузку. Открытый выбор роли — сознательное упрощение демо, не production-аутентификация. Не загружайте настоящие персональные или коммерческие данные.

## Функции

- Форма ТЗ: название, оффер, GEO, тип, количество, описание, до пяти референсов, приоритет, дедлайн.
- Kanban: Новые → В работе → На проверке → Правки → Готово. Кнопки и перенос в допустимые колонки; сдача/правки открывают форму.
- Свободную задачу берёт креативщик. Только исполнитель сдаёт результат и пишет расходы, только автор-байер принимает/возвращает. Аналитика доступна руководителю, проверяется сервером.
- Ссылки и до пяти файлов за сдачу: 5 МБ каждый, PNG/JPG/WebP/PDF/MP4/ZIP/TXT. R2, доступ к файлам только внутри своей песочницы.
- Серверные даты создания, взятия, каждой сдачи и принятия, журнал действий и статусов.
- AI-кредиты по сервисам, исполнителям и итерациям, включая правки. Разные сервисы не складываются в деньги.
- Аналитика количества/статусов, загрузки, просрочек, среднего активного времени и полного цикла, AI-расходов.
- Поиск, фильтры, адаптивный интерфейс. Время на доске — МСК. Поле дедлайна вводится в часовом поясе устройства и передаётся как UTC.

## Архитектура

React 19 + TypeScript, Vinext/Vite, Cloudflare Worker API, D1 (SQLite), R2.

- `lib/model.ts` — чистая модель команд, переходов, расчётов и seed.
- `lib/server.ts` — сессии, авторизация, валидация, D1/R2 и CSRF Origin.
- `app/api/[...path]/route.ts` — HTTP API.
- `app/page.tsx` — доска, формы и аналитика.
- `db/schema.ts`, `drizzle/` — схема и миграция.
- `tests/` — предметные и HTTP-интеграционные проверки.

Для прототипа команда хранится JSON-документом в D1 с версией и compare-and-swap UPDATE. Конфликт даёт 409, не перезаписывает чужую команду. Сессии отдельные, cookie содержит случайный токен, БД — SHA-256. Cookie: HttpOnly, SameSite=Lax, Secure на HTTPS. Тестовым ролям видны все задачи их команды; команды изменения ограничены ролями, автором и исполнителем. localStorage для записей не используется.

Активное время — календарное время статусов «В работе» и «Правки». Полный цикл — от первого взятия до принятия, включая проверку. Это не табель оплаченных часов. Средние — только по завершённым задачам, без них «—».

## Локальный запуск

Node.js 24, npm и Git. Эта версия использовалась для сборки и тестов; импорт TypeScript в тестах использует встроенную поддержку Node 24.

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run db:migrate:local
npm start -- --port 5180
```

Открыть http://127.0.0.1:5180 . D1/R2 эмулируются локально, внешние API-ключи не нужны. Миграцию выполнить **один раз** на новой `.wrangler/state`. Для изменений схемы создавать новую миграцию. После сборки с правками перезапустить сервер.

HMR: `npm run dev -- --port 5180` после создания локальной БД. Оба preview используют `.wrangler/state`.

HTTP-проверка при запущенном сервере: `npm run test:api`. Другой адрес можно передать через `TEST_BASE_URL`. Тест создаёт отдельную песочницу с вымышленными данными.

## API и ограничения

`POST /api/session`, `GET /api/state`, `POST /api/command` (create/claim/credit/submit/revise/approve + version), `GET /api/analytics`, `POST /api/upload`, `GET /api/files/:id`. Мутации требуют совпадения Origin.

Это прототип, не готовая CRM: нет регистрации, приглашений, realtime push, уведомлений и биллинга провайдеров. Для продакшена нужны аутентификация и членство, нормализованные таблицы/индексы, антиабьюз и инфраструктурные квоты, очистка истёкших песочниц/непривязанных файлов, проверка загрузок, мониторинг и бэкапы. Демо ограничено 100 задачами и 30 файлами на пространство. После конфликта нужно обновить доску и повторить действие.

Не официальный продукт AFF SAINTS. Пользователи, офферы и показатели вымышлены.
